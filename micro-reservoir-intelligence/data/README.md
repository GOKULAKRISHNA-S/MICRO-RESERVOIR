## 3. Supplying Genuine Satellite Observations (No Source Code Edits Needed)

You can supply genuine satellite observations directly through the **Streamlit Dashboard** (`Mode 1: Local GeoTIFF Files`) without modifying any source code:

### Step 1: Obtain Two Temporally Separated Observations
1. **Baseline Date ($t_0$)**: Post-monsoon reference date (e.g., October/November) when reservoir is near capacity.
2. **Comparison Date ($t_1$)**: Subsequent dry-season monitoring date (e.g., March/April) or post-rain date.
3. *Temporal Rule*: The baseline date must strictly precede the comparison date (`date_0 < date_1`).

### Step 2: Ensure Compatible Band Inputs
For each observation date, obtain:
* **Green Band**: Sentinel-2 **B03** (or Landsat-8/9 Band 3), nominal 10m resolution.
* **Near-Infrared (NIR) Band**: Sentinel-2 **B08** (or Landsat-8/9 Band 5), nominal 10m resolution.
* *Optional Cloud Mask*: Sentinel-2 Scene Classification Layer (SCL) or external cloud mask.

### Step 3: Verify Geospatial Consistency
Both observations must share:
* **Identical Projected Planar CRS**: e.g., UTM `EPSG:32643` (unprojected `EPSG:4326` degrees is rejected).
* **Identical Spatial Dimensions**: Matching height and width in pixels.
* **Aligned Transform Origin**: Bounding box origins within 0.001 m tolerance.
* *Tip*: Clip both observations to your reservoir Area of Interest (AOI) polygon using GDAL or QGIS before loading:
  ```bash
  gdalwarp -cutline reservoir_aoi.geojson -crop_to_cutline -t_srs EPSG:32643 B03.jp2 B03_clipped.tif
  gdalwarp -cutline reservoir_aoi.geojson -crop_to_cutline -t_srs EPSG:32643 B08.jp2 B08_clipped.tif
  ```

### Step 4: Run in Dashboard
1. Launch `streamlit run app.py`.
2. Select **Mode 1: Local GeoTIFF Files**.
3. Enter Reservoir ID, Observation Dates, and file paths.
4. Click **🚀 Run Surface Water Analysis**.

## 4. Supported Input Layouts

The loader strictly validates local GeoTIFF files before water extraction. Two documented layouts are supported:

### Layout 1: Separate Single-Band Files (Recommended)
Individual single-band GeoTIFF files mapped explicitly by spectral band name:
```python
from src.microreservoir import load_geotiff_observation

obs = load_geotiff_observation(
    scene_id="S2A_20240315_T43QGE",
    date_str="2024-03-15",
    band_files={
        "green": "data/imagery/20240315_B03_10m.tif",  # Sentinel-2 B03 (Green)
        "nir": "data/imagery/20240315_B08_10m.tif",    # Sentinel-2 B08 (NIR)
        "red": "data/imagery/20240315_B04_10m.tif",    # Optional: True/False color
        "swir1": "data/imagery/20240315_B11_10m.tif",  # Optional: MNDWI / AWEI
    },
    cloud_mask_file="data/imagery/20240315_cloud.tif", # Optional: 1=cloud/shadow, 0=clear
)
```
* **Enforced Validation**: All band rasters must have identical pixel dimensions ($H \times W$), identical CRS, and identical affine transform matrices. Mismatched shapes or projections trigger `IncompatibleGridError`.

### Layout 2: Multiband File with Explicit Band Mapping
A composite multiband GeoTIFF file accompanied by an explicit, 1-indexed band mapping dictionary:
```python
obs = load_geotiff_observation(
    scene_id="S2A_20240315_T43QGE",
    date_str="2024-03-15",
    multiband_file="data/imagery/20240315_stacked.tif",
    band_mapping={
        "green": 1,  # Band 1 corresponds to Green
        "nir": 2,    # Band 2 corresponds to NIR
        "red": 3,    # Band 3 corresponds to Red
    },
)
```
> [!IMPORTANT]
> **Strict Band Mapping Rule**: The loader will **never silently assume** that a raster's band index corresponds to a specific Sentinel-2 band. Omission of `band_mapping` for multiband files raises `MissingBandError`.

## 3. Metadata Requirements & Ground Truth Integrity

> [!CAUTION]
> **Never Invent Observation Dates or Satellite Metadata.**  
> Artificial or guessed acquisition dates can corrupt seasonal hydrologic drawdown assessments. Always extract ground-truth observation dates and metadata directly from the official satellite provider's product manifest (`MTD_TL.xml`, `MTD_MSIL2A.xml`, or MTL text files).

| Metadata Field | Extraction Source | Format / Constraint |
| :--- | :--- | :--- |
| **`scene_id`** | Provider Granule/Tile ID (e.g. `L2A_T43QGE_A045582_20240315T052650`) | String |
| **`date`** | Satellite sensing date from metadata header (`DATATAKE_1_DATETIME`) | Strict ISO-8601 (`YYYY-MM-DD`) |
| **`pixel_resolution_m`** | Spatial Ground Sampling Distance (GSD) from affine transform | Positive float (e.g., `10.0` meters) |
| **`crs`** | Projected Coordinate Reference System from GeoTIFF header | Projected CRS with linear meters (`EPSG:32643`) |
| **`cloud_cover_percent`** | Scene Classification Layer (SCL) or provider QA band | Float `[0.0, 100.0]` or `None` if unassessed |

### Cloud Mask Trustworthiness
If no trustworthy cloud mask or official cloud metadata is supplied, `cloud_cover_percent` is recorded as `None` and `cloud_assessed` is set to `False`. The system **never claims cloud detection or a passed cloud check** when no trustworthy cloud information exists.

## 4. Obtaining Multispectral Imagery

All processing is **100% local**. No satellite API, credentials, or active internet connection is required during execution. You can acquire free, open satellite imagery from the following sources:

### 1. Copernicus Data Space Ecosystem (CDSE)
* **URL**: [dataspace.copernicus.eu](https://dataspace.copernicus.eu/)
* **Recommended Product**: Sentinel-2 Level-2A (Bottom-of-Atmosphere surface reflectance).
* **Bands to Download**:
  * `B03_10m.jp2` (Green, ~560 nm, 10m resolution)
  * `B08_10m.jp2` (NIR, ~842 nm, 10m resolution)
  * `B04_10m.jp2` (Red, ~665 nm, 10m resolution)
  * `B11_20m.jp2` (SWIR1, ~1610 nm, resampled to 10m)
  * `SCL_20m.jp2` (Scene Classification Layer for cloud/shadow masking)

### 2. USGS EarthExplorer
* **URL**: [earthexplorer.usgs.gov](https://earthexplorer.usgs.gov/)
* **Recommended Product**: Landsat 8/9 OLI/TIRS Collection 2 Level-2 (Surface Reflectance).
* **Bands to Download**: Band 3 (Green, 30m), Band 5 (NIR, 30m), Band 4 (Red, 30m), QA_PIXEL (Quality assessment).

### 3. AWS Open Data Registry
* **Sentinel-2 Cloud-Optimized GeoTIFFs (COGs)**: [registry.opendata.aws/sentinel-2](https://registry.opendata.aws/sentinel-2/)
* Enables direct download of individual band `.tif` files without extracting full Multi-Gigabyte `.SAFE` archives.

## 6. Spatial Alignment & Grid Rejection Rules

* **Zero Silent Resizing**: If baseline and comparison scenes have differing spatial shapes, bounding boxes, or CRSs, the pipeline strictly raises [`IncompatibleGridError`](file:///c:/Users/gokul/Documents/MICRO-RESERVOIR/micro-reservoir-intelligence/src/microreservoir/exceptions.py#L38) rather than silently interpolating or warping pixels.
* **Temporal Precedence**: The baseline date must strictly precede the comparison date. Reversed or identical observation dates are rejected with [`TemporalOrderError`](file:///c:/Users/gokul/Documents/MICRO-RESERVOIR/micro-reservoir-intelligence/src/microreservoir/exceptions.py#L46).
* **Path Safety**: File paths are validated against path traversal (`../`) and null bytes (`\0`) via [`validate_safe_path`](file:///c:/Users/gokul/Documents/MICRO-RESERVOIR/micro-reservoir-intelligence/src/microreservoir/geotiff.py#L33).
